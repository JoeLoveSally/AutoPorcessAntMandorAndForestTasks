# 蚂蚁庄园与蚂蚁森林自动化系统设计

## 1. 目标

系统在 WSL 中运行，通过 ADB 控制 Android 手机，自动完成支付宝蚂蚁庄园和蚂蚁森林中规则固定的日常任务。

当前运行边界是单机、单设备、人工触发的一次执行。Windows 只负责将 USB 设备共享给 WSL；任务判断、设备控制、日志和截图均在 WSL 中完成。

系统不追求成为通用 Android Agent。支付宝当前页面是事实来源，程序只执行经过识别和验证的确定性动作。

## 2. 核心原则

每个步骤遵循同一个闭环：

```text
观察页面 -> 识别状态 -> 决定动作 -> 执行动作 -> 验证结果
```

- 不按录屏坐标和固定等待时间机械回放。
- 每次只执行一个可验证的原子动作。
- 关键动作统一声明源页面、目标元素、目标页面和完成标记；任一条件不满足都不继续。
- 页面未知或目标不确定时停止点击。
- 所有循环都有次数和时间上限。
- 恢复后重新读取支付宝状态，不盲目沿用旧坐标。
- 必需任务资源不足或无法验证时，本次运行报失败。

## 3. 总体结构

```text
src/runtime
  -> workflow
      -> state_machine
          -> screen_perception -> device_bridge
          -> action_executor   -> device_bridge

workflow -> web_search
src/runtime -> logger
src/runtime -> runtime/（运行数据）
```

普通页面使用 ADB 截图、UI Tree 和 ADB 输入。能量雨使用独立的实时视频与低延迟触控通道，但仍通过同一台 ADB 设备建立连接。

## 4. 组件职责

### `src/device_bridge`

隔离所有手机通信细节。

- `common`：设备接口、坐标、边界、屏幕尺寸和方向换算。
- `adb`：截图、UI dump、点击、滑动、返回、启动应用和前台页面查询。
- `realtime`：scrcpy 视频流、H.264 解码、低延迟触控和延迟统计。

上层组件不能直接执行 ADB 或 scrcpy 命令。

### `src/domain_data`

存放不依赖具体实现的数据模型，例如 Observation、Page、Overlay、Element、ActionResult 和 TaskResult。这些是 Python 类型定义，不是运行时生成的数据文件。

### `src/screen_perception`

负责回答“当前看到了什么”，不决定业务动作。

- 解析 UI Tree。
- 识别页面和覆盖在页面上的弹窗。
- 执行模板匹配、局部文字识别和视觉检测。
- 识别并跟踪能量雨中的能量球。
- 返回识别依据和可信度。

页面和弹窗分别建模，避免一个新弹窗使整个底层页面变成 UNKNOWN。

### `src/action_executor`

负责安全执行动作：

1. 校验页面和元素来自最新观测。
2. 将截图或视频坐标转换为设备坐标。
3. 执行点击、滑动或返回。
4. 获取新观测并验证后置条件。

关键点击使用统一动作契约：点击前检查页面、Activity、目标元素、观测稳定性和观测年龄；完整观测默认在 6 秒后过期，以覆盖当前设备约 2 至 3 秒的识别耗时，同时限制旧坐标生命周期。点击后检查目标页面以及必须出现、至少出现一个或必须消失的完成标记。后置观测处于页面切换期时，会在有限窗口内再次确认。没有通过前置校验的动作不会发送到手机；不可逆动作一旦已发送，即使后置条件不明也不会自动重发。

### `src/state_machine`

提供通用状态机能力，包括状态转换、原子步骤、超时、重试次数和步骤结果。它不包含庄园或森林的具体业务规则。

### `src/workflow`

描述业务顺序并组合状态机、感知和动作组件。

- `manor`：庄园主页、家庭和领饲料任务。
- `forest`：收自己能量、偷好友能量、浇水和能量雨。
- `shared`：庄园和森林共用的广告、抽奖等流程。
- `recovery`：等待稳定、关闭已知弹窗、安全返回、重进任务入口和重新探测任务状态。

### `src/web_search`

负责庄园小课堂的网页搜索、答案提取和答案缓存逻辑。搜索不能唯一确定答案时，由 Workflow 决定失败或使用后备策略。运行时产生的缓存文件写入项目根目录的 `runtime/`。

其他外部能力以后各自建立独立组件，不集中放入通用 services 目录。

### `src/logger`

实现结构化日志记录，负责记录动作、状态转换、重试、耗时和失败原因。日志文件写入项目根目录的 `logs/`；需要截图时写入 `screenshots/runs/`，并在日志中记录截图文件名。

### `src/runtime`

这是运行编排的源代码组件。它读取配置、连接设备、组装组件、创建一次运行，并负责读写 Resume 状态。CLI 只调用 Runtime，不直接包含业务逻辑。

### `runtime`

这是项目根目录下的运行数据目录，不是源代码组件。Resume 数据库、检查点、搜索缓存和进程锁等运行时文件统一放在这里，不放入 `src/`。

### `config`

位于项目根目录，保存可提交的示例配置和本机配置。密钥只通过环境变量或未提交的本机配置读取。

## 5. Workflow 顺序

庄园严格按以下顺序执行：

```text
主页 -> 家庭 -> 领饲料
```

森林严格按以下顺序执行：

```text
收自己能量 -> 偷好友能量及抽奖 -> 浇水 -> 天天能量雨
```

每个任务先探测 `待执行`、`已完成`、`未出现`或`异常`，再决定执行、跳过或失败。动态任务通过页面状态和完成标记退出循环。

## 6. 原子步骤与 Resume

以每日捐蛋为例：

```text
打开项目 -> 打开确认页 -> 确认捐1颗 -> 验证家庭任务显示(1/1)
```

如果程序在确认捐蛋后退出，`runtime/`中的记录可能仍是 IN_PROGRESS。重新运行时，Runtime 读取记录，Workflow 返回家庭任务页；若页面已经显示 `(1/1)`，则更新为 SUCCESS 并继续后续任务，不会再次捐蛋。

不可逆动作在点击前写入 `IN_PROGRESS`，验证成功或明确失败后再写入终态。启动时会读取各步骤跨运行的最新记录并报告仍处于 `IN_PROGRESS` 的步骤；该记录用于提示恢复范围，不替代支付宝页面探测。捐蛋、请客、答题、做美食、合种浇水、抽奖确认和每轮能量雨均使用这一检查点边界。

运行记录只表示程序最后确认到哪里。恢复时仍需重新观察支付宝页面，并以支付宝当前状态为准修正本地记录，不能根据旧记录直接发送下一次点击。

常用步骤状态包括：

- `PENDING`：尚未开始。
- `IN_PROGRESS`：动作已开始，结果尚未确认。
- `SUCCESS`：已验证完成。
- `ALREADY_DONE`：执行前已经完成。
- `SKIPPED`：可选任务未出现。
- `FAILED`：必需任务无法完成或验证。

## 7. 恢复策略

遇到预期外页面时按固定顺序处理：

1. 停止点击并保存当前状态。
2. 等待页面加载稳定后重新识别。
3. 关闭已知弹窗。
4. 校验目标页面、Activity、必要元素、禁止元素和遮罩状态，而不只比较页面类型。
5. 在允许的页面执行一次安全返回。
6. 按当前任务保存的重进路径重新进入入口并探测完成状态。
7. 超过恢复预算后记录日志和截图并报失败。

恢复策略不使用“点击右上角大概位置”一类通用猜测。普通可重复动作只有在源上下文被重新确认后才允许重试；已经发送的不可逆动作只恢复和核验，不重发。

## 8. 运行产物

```text
logs/<run-id>.jsonl
screenshots/runs/<run-id>/<index>-<reason>.png
screenshots/runs/<run-id>/energy-rain-replay/<round>/frame-*.jpg
screenshots/runs/<run-id>/energy-rain-replay/<round>/frames.jsonl
runtime/task_state.db                 # 使用 SQLite 时
runtime/checkpoints/<run-id>.json     # 使用 JSON 检查点时
runtime/cache/                        # 搜索等运行缓存
```

`logs/`记录发生过什么；`runtime/`保存程序继续运行所需的状态；`screenshots/runs/`保存关键页面和能量雨限量回放样本。能量雨样本标注检测点与点击点，并配套逐帧 JSONL；写入使用有界异步队列，磁盘繁忙时允许丢弃诊断样本而不阻塞实时点击。示例素材和匹配模板分别保留在 `screenshots/demo/` 和 `screenshots/template/`。

源代码与运行产物的边界如下：

```text
src/          Python 实现代码
config/       配置文件
runtime/      Resume 数据库、检查点、缓存和临时运行状态
logs/         运行日志
screenshots/  示例、模板和运行截图
docs/         设计文档
tests/        测试代码与测试数据
```
